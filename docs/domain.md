# 领域约定：观测订单编排

PIESAT-2 多颗卫星入轨并具备星上智能处理能力后，本服务统一编排应急观测、常规测绘与重复区域更新三类需求，在有限的成像机会、能源与星上存储之间作取舍。

## 编号、时间与数据边界

- 卫星、订单、订阅方、机会、计划等外部主体一律使用不含真实身份信息的引用编号（如 `PIESAT-2-A`、`ORD-EM-1`、`sub-em`）。
- 所有时间采用带偏移量的 ISO 8601 字符串，落库统一为 UTC。
- 卫星状态、机会预报、执行回执、分片到达等外部事实必须携带 `source_ref` 与 `source_sequence`；同一来源序列号只接受一次，保留来源系统对事实的责任边界。
- 附件与影像数据不落库，只记录受控引用与 `sha256` 摘要。

## 订单登记

每份观测订单统一登记：目标范围（GeoJSON 或 bbox）、允许成像时间、允许成像模式、时效等级（`emergency | routine | refresh`）、交付对象、数据授权范围 `data_scope` 与使用边界、星上存储占用、交付截止时间。

交付对象必须事先登记且其授权范围覆盖订单的 `data_scope`，否则登记即被拒绝——不同授权范围之间不得擅自共享数据。

## 重复目标与合并

- 登记时按目标名称、别名（归一化后）与几何覆盖检测重复下单，生成**合并提示**。
- 提示只提示，不自动合并；任务经理可显式接受或忽略。
- 两份订单 `data_scope` 不同：提示中标注 `scope_compatible=false`，只可协调排期，**禁止合并与数据共享**，接受合并会被拒绝（`scope_crosses_boundary`）。

## 候选、计划与冻结

- 候选计划按“每颗卫星的能力版本 × 每个在预报中的成像机会”计算可行性：模式匹配、时间窗重叠、目标覆盖率（阈值 0.95）、卫星可用性、存储与能耗预算。
- 评分用于解释“为什么选中这颗星”：交付时限裕度、时效契合（应急越早越好、更新越新越好、常规居中）、星上智能能力、资源余量、首选模式、覆盖质量，评分因子全部留痕。
- 草稿可反复重算；冻结时逐条复核机会与卫星状态，并由数据库部分唯一索引保证**同一成像机会只能被一个占用中的分配使用**。

## 应急插单

- 应急订单可对指定（或排名第一的）可行机会发起插单，系统返回**将要被挤出的订单明细**并生成 `pending` 批准单。
- 未经批准不产生任何分配；批准必须携带 `approver_ref`。
- 批准执行时再次核验占用：若批准期间出现未向批准人展示的新占用，拒绝执行并要求重新发起。
- 被挤出的订单释放机会、进入重排队列，事件时间线记录挤出方、批准人与批准单。

## 重排

三类触发只影响命中的订单，其他订单的冻结计划不动：

- `spacecraft_unavailable`：该星上未来的占用分配取消；
- `opportunity_revised`：旧机会标记 `superseded`，仅引用旧机会且未执行的分配取消，新机会接续；
- `receipt_late` / `receipt_failed`：超过机会预计回执时限仍无确认的未交付订单进入重排。

重排一次性重算候选、按优先级（应急优先、其余按截止时间）选取未被占用的机会并直接冻结为新计划；找不到可行机会的订单保留在重排队列。**已经汇聚交付的数据产品继续引用原计划与原机会**，晚到回执不对其产生任何影响。

## 数据分片、版本与订阅

- 分片按 `(allocation_id, shard_index, product_version)` 记录校验摘要；同序号不同摘要判定冲突，需走重处理。
- 产品版本由有序分片摘要与处理配方汇聚出明确的聚合摘要；缺片产生可追踪的 `shard_missing` 通知，齐片后状态转为 `assembled`。
- 重处理开启新版本（可携带原分片、指定新配方），旧版本标记被取代；撤回将版本置为 `withdrawn`。缺片、汇聚、重处理、撤回均向订阅方产生去重的、可确认（acked）的状态通知。
- 订阅与产品必须在同一 `data_scope`。

## 按订单解释

`GET /orders/:id/explain` 汇总：选中某颗星的评分依据与备选、全部改排经历（触发来源、原分配、新分配）、实际交付的产品版本清单，以及超期责任归因。责任沿时间线分段计算，落在具体环节：任务经理、星上段、轨道预报、地面段或应急抢占。
